# af candidate options

Reference for `agents-skills/af/SKILL.md`: the per-candidate options of a role in `af.config.json` (`tools`, `env_allow`, `base_url`, `api_key_command`, `quota_provider`, `quota_windows`). Read it when writing or reviewing a role's candidates.

Pi candidates may set `tools` to a non-empty list passed to Pi with MCP disabled. Without a shell tool, the worker cannot run `wrangler`, `gh`, `git`, or `curl`; Pi's `write` and `edit` tools are not path-confined. On Claude candidates, `tools` removes the shell tool (the CLI is started with `--tools`, `--permission-mode acceptEdits` and `--strict-mcp-config`), but native Claude candidates (no `base_url`) pass no flag that turns off user or project settings or hooks, so hooks and settings `env` entries still apply, and the file tools are not confined to the worktree. `env_allow` may be empty and keeps standard runtime, locale, proxy, and CA variables plus listed names set in the parent. It removes tokens from the environment, but not credential files on disk or Pi's own credential file. Claude Code CLI candidates use `model` and accept the same optional `tools` (passed as `--tools ... --permission-mode acceptEdits --strict-mcp-config`) and `env_allow`. Claude candidates also accept `base_url` plus `api_key_command` (both required together, `https://` only), which point the Claude CLI at another vendor's Anthropic-compatible endpoint: af then starts `claude --bare --setting-sources ""` (and adds `--permission-mode acceptEdits` when no `tools` is set, since the empty setting-sources also drops user permission settings; `--bare` alone does not stop the CLI applying a user settings `env` block over the injected URL; the empty setting-sources value isolates user, project, and local settings), runs the command for the key, passes it as `ANTHROPIC_API_KEY` with `ANTHROPIC_BASE_URL`, and removes `ANTHROPIC_AUTH_TOKEN`; a failed or empty key command fails the attempt without starting the CLI.

Any candidate may set `quota_provider` (nonempty string matching the `provider` in the magpie quotas feed, for example `"codex"` or `"copilot"`) and `quota_windows` (nonempty array of window names such as `["5 hours", "7 days"]`; default: every window of that provider). With the top-level `quota_ceiling_percent` set, af skips the candidate when a watched window has `used` at or above the ceiling; a candidate without `quota_provider` is never skipped. Unlimited windows are ignored, an account entry whose `balance` shows a positive amount (for example `"5761.98 credits"`) is not skipped, and an unreachable feed does not skip anyone.
